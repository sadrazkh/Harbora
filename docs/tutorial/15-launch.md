# ۱۵ — راه انداختن اپ

کدتان را می‌دهید. دیتابیس، اتصال، استقرار و بررسی سالم بودن را Harbora انجام می‌دهد.

1. منوی کناری › **راه انداختن اپ** (`/launch`).
2. آدرس مخزن گیت را بدهید، یا پوشهٔ پروژه را zip کنید و بیندازید. **بخوانش**.
3. صفحهٔ **این را پیدا کردم** می‌گوید چه پیدا شده، چه ساخته می‌شود و چقدر هزینه دارد. تا اینجا چیزی ساخته نشده و پولی کم نشده. فقط چیزی را می‌پرسد که خودتان باید بدانید، مثل `STRIPE_SECRET_KEY`.
4. **راه بینداز**. قدم‌ها یکی‌یکی جلو می‌روند؛ می‌توانید صفحه را ببندید.
5. آخرش آدرس اپ را می‌بینید.

همین. بقیهٔ این صفحه برای وقتی است که چیزی جلو نرفت.

## چه چیزی را می‌خواند، و چه چیزی را نه

| فایل | نتیجه |
|---|---|
| `Dockerfile` | با همین ساخته می‌شود و بر بقیه مقدم است |
| `package.json`، `*.csproj`، `go.mod`، `composer.json`، `requirements.txt`، `pyproject.toml`، `Pipfile` | زبان؛ و از وابستگی‌ها، چه سرویسی لازم است و وب است یا ربات |
| `package.json` با اسکریپت `build` و بدون `start` واقعی (Vite، Create React App و مانندش) | فرانت‌اند: ساخته می‌شود و خروجی‌اش روی وب نشان داده می‌شود. متغیرهای عمومی مثل `VITE_` و `REACT_APP_` هنگام ساخت خوانده می‌شوند، داخل فایل‌های سایت می‌روند و هر بازدیدکننده‌ای آن‌ها را می‌بیند؛ برای عوض کردنشان باید دوباره مستقر کنید |
| `index.html` | سایت ساده |
| `docker-compose.yml` | استک Compose، اگر چیز دیگری نباشد؛ وگرنه از `image:` می‌فهمد چه سرویسی لازم است |
| `Procfile` | `worker:` یعنی پس‌زمینه، با همان دستور |
| `.env.example` و مانندش | نام متغیرها: بعضی را وصل می‌کند، رمزهایی مثل `JWT_SECRET` را می‌سازد، فقط بقیه را می‌پرسد |
| `prisma/`، `artisan`، `alembic.ini` | دستور ساختن جدول‌ها پیش از اجرا |

**`.env`** و هر فایل env دیگری را که مقدار واقعی دارد، مثل `.env.production`، باز نمی‌کند و از zip کنار می‌گذارد، همین‌طور `node_modules` را. برای همین از مرورگر فقط zip قبول می‌شود: فایل `.tar.gz` چنین فیلتری ندارد و کارِ ترمینال است، که پیش از فرستادن خودش فیلتر می‌کند. **کد شما** را هم نمی‌خواند: متغیری را که فقط در کد آمده در `.env.example` بنویسید.

## «وصل شدن» یعنی چه

اپ فقط باید متغیرها را بخواند و روی `0.0.0.0` گوش بدهد. `localhost` داخل کانتینر خود اپ است، نه دیتابیس.

```js
const db = new Pool({ connectionString: process.env.DATABASE_URL });
server.listen(process.env.PORT || 3000, "0.0.0.0");
```

```python
db = psycopg.connect(os.environ["DATABASE_URL"])
app.run(host="0.0.0.0", port=int(os.environ.get("PORT", 5000)))
```

* **نام‌ها:** `DATABASE_URL` (PostgreSQL، MySQL، MariaDB)، `MONGODB_URI`، `REDIS_URL`، `AMQP_URL`، `NATS_URL`، `MEILI_URL`، و جزءبه‌جزء مثل `PGHOST`. فهرست کامل در صفحهٔ اپ است: **اپ چطور این‌ها را می‌خواند؟** ‎.NET خودش `ConnectionStrings__DefaultConnection` را می‌خواند.
* **نام دیگری می‌خوانید؟** (`DB_HOST`، `MONGO_URI`، `POSTGRES_PASSWORD`، `CACHE_URL`، …) همان را در `.env.example` بنویسید تا به همان مقدار وصل شود، حتی بعد از تعویض رمز.
* **دیتابیس خودتان را دارید؟** (مثلاً Neon) تیک همان دیتابیس را بردارید و در **جزئیات** › **دیتابیس را جای دیگری داری؟** مقدار `DATABASE_URL` را بنویسید. چیزی که اینجا بنویسید متغیر خود اپ می‌شود و بر اتصال مقدم است، حتی اگر دیتابیس تیک خورده باشد. اگر خالی بماند و دیتابیسی هم نباشد، تنظیم نمی‌شود و در قدم‌ها نامش را می‌بینید.
* **`PORT`** را Harbora به هر اپ وب می‌دهد: همان پورتی که ترافیک به آن می‌رسد. اگر `Dockerfile` خودتان آن را نمی‌خواند، روی پورتی گوش بدهید که `EXPOSE` کرده‌اید.
* **دیتابیس خالی ساخته می‌شود.** دستور ساختن جدول‌ها را برای Prisma، Laravel و Alembic خودش پیشنهاد می‌کند؛ برای بقیه: **جزئیات** › **دستور پیش از اجرا**. بعد از ساخته شدن اپ، از کارت **دستور پیش از انتشار** در صفحهٔ اپ عوضش کنید.

## خواندن بررسی‌ها

| بررسی | یعنی | اگر نشد |
|---|---|---|
| **در حال اجراست** | کانتینر الان روشن است | لاگ را بخوانید و دوباره مستقر کنید |
| **بالا مانده** | در این استقرار ری‌استارت نشده | **مدام از کار می‌افتد**: خط‌های آخر لاگ همان‌جاست |
| **روی شبکهٔ این اپ جواب می‌دهد** | Harbora با نام کاربری و رمز خود دیتابیس، از شبکهٔ این اپ وصل شد. **نه اینکه کد شما وصل شده** | ببینید دیتابیس روشن است |
| **آدرسش از بیرون کار می‌کند** | از بیرون جواب آمد. ۴۰۴ هم قبول است، پس خودتان هم بازش کنید | **در انتظار** تا چند دقیقه طبیعی است (گواهی SSL). بعدش DNS و پورت ۸۰ |
| **در لاگش مشکلی دیده نشد** | ۲۰۰ خط آخر خطای شناخته‌شده‌ای ندارد | هشدار خودش می‌گوید. `ECONNREFUSED 127.0.0.1:5432` یعنی کد `DATABASE_URL` را نمی‌خواند |

**بررسی نشد** یعنی نمی‌دانیم، نه اینکه درست است: MongoDB، RabbitMQ و NATS خودکار آزمایش نمی‌شوند. **اپت بالاست** یعنی چیزی خراب پیدا نشد و روشن بودنش ثابت شد، ولی کنارش ممکن است «بررسی نشد» هم باشد، پس خط‌ها را بخوانید. در صفحهٔ هر اپ: **بررسی کن**.

## وقتی می‌گوید نمی‌شود

| می‌بینید | چه کار کنید |
|---|---|
| **این مخزن چند اپ دارد** | یک پوشه را بزنید؛ بقیه را جدا راه بیندازید |
| **نشد کدت را بخوانم.** | آدرس غلط است یا مخزن خصوصی: توکن بدهید (**مخزن خصوصی است؟**). `git@…` نه، `https` |
| zip پروژه‌ای که فقط Compose دارد | از گیت راه بیندازید، یا `Dockerfile` اضافه کنید |
| **از مرورگر فقط zip می‌گیرم** | `.tar.gz` فرستاده‌اید: پوشه را zip کنید |
| خطا به‌جای هزینه | با **برو به صورت‌حساب** کنارش، موجودی کم است. بدون آن، پول درستش نمی‌کند: **جزئیات** › اندازهٔ دیگر |
| **اپ بالا آمد، ولی یک چیز درست نیست** | مثلاً کرش می‌کند. همان خط می‌گوید چه کنید |
| **بالا آمد، ولی نتوانستم مطمئن شوم که کار می‌کند** | چیزی خراب پیدا نشد، ولی بررسی انجام نشد؛ همان‌جا نام می‌برد کدام. خودتان بازش کنید و در صفحهٔ اپ **بررسی کن** |
| **اینجا گیر کرد: استقرار** | بیلد شکست خورد یا اپ بالا نیامد: **لاگ** کنار همان قدم |
| **یک ساخت هنوز در جریان است** | نسخهٔ تازه را وسط یک ساخت فرستاده‌اید و اجرا نشد: وقتی تمام شد، دوباره بفرستید |
| **این اپ بعداً پاک شده** | چیزی برای باز کردن نمانده. اگر دیتابیسی مانده، همان‌جا نام و لینکش هست |
| زبان شناخته نشد، Django، یا یادداشتی دربارهٔ `package.json` کنار زبان دیگر | یک `Dockerfile` اضافه کنید |

**دوباره امتحان کن** فقط چیزی را می‌سازد که نیست. آنچه تایپ کرده بودید نگه داشته نمی‌شود؛ پیام نامش را می‌گوید. zip یک بار مصرف می‌شود: نسخهٔ تازه را از صفحهٔ اپ بفرستید.

وقتی جایی گیر کند، چیزی پاک نمی‌شود. آنچه ساخته شده زیر پیام با لینک فهرست می‌شود، چون ممکن است هزینه داشته باشد: اگر لازمش ندارید، از صفحهٔ خودش پاکش کنید.

## از ترمینال

```bash
harbora login    # یک بار
cd my-app
harbora launch
harbora launch --yes --set TELEGRAM_BOT_TOKEN="$TOKEN"    # در CI
harbora launch --no-service postgres --set DATABASE_URL="$NEON_URL"    # دیتابیس خودتان
```

پوشه را بدون `.env` می‌فرستد. `--yes` نمی‌پرسد، `--set` جواب سؤال را از قبل می‌دهد، `--no-service` سرویسی را نمی‌سازد و نام متغیرهایی را که بی‌جواب می‌مانند می‌گوید، بقیه در `harbora launch --help`. بدون ترمینال و بدون `--yes` چیزی نمی‌سازد.

کد خروج: `0` بالا آمد؛ `1` جلو نرفت، یا اپ بعداً پاک شده؛ `2` بالا آمد ولی یک بررسی **مشکل دارد**، یا نشد مطمئن شویم کار می‌کند.

## بعدش

* **از پوشه:** `harbora deploy`؛ `harbora.yml` نوشته شده.
* **از گیت:** صفحهٔ اپ › **استقرار خودکار (Git)**: آدرس Webhook و سکرت را یک بار در تنظیمات مخزن بگذارید تا هر push مستقر شود.
* **از zip:** صفحهٔ اپ › **نسخه‌ی تازه**.

فرم دستی سر جایش است: **برنامه‌ها** › **فرم کامل** ([فصل ۳](03-applications.md)).
