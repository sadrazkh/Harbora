# ۱۰ — ربات تلگرام (long-polling)

بات تلگرام یکی از قدیمی‌ترین و جاافتاده‌ترین کانال‌های کسب‌وکار ایرانی است: پشتیبانی مشتری، ثبت
سفارش، اطلاع‌رسانی. این فصل یک قالب آماده در بازار Harbora را با یک ربات واقعی — هرچند ساده — به هم
وصل می‌کند.

> این فصل، برخلاف بقیهٔ کتاب، تصویر ندارد: عکس‌ها از یک پنل در حال اجرا گرفته می‌شوند، و این جلسه
> به چنین پنلی (و به Docker) دسترسی نداشت. متن زیر از روی خودِ کد پنل نوشته شده، نه از روی حدس —
> نام فیلدها، مسیرها و برچسب‌ها همان چیزی‌اند که در سورس هست.

## قالب چه می‌سازد

**قالب‌ها** › **Telegram Bot (long-polling)** یک اپ از نوع **Worker** می‌سازد: یک پردازهٔ همیشه در
حال اجراست که خودش با تلگرام تماس می‌گیرد (long-polling)، نه برعکس. چون هیچ درخواست HTTP ورودی‌ای
ندارد، این اپ **هیچ دامنه و آدرس عمومی‌ای نمی‌گیرد** — نه چیزی برای باز کردن روی اینترنت هست، نه
webhook ای برای تنظیم. دقیقاً همان چیزی که در تعریف نوع سرویس Worker آمده: «همیشه در حال اجرا،
بدون ترافیک ورودی — صف، زمان‌بند، مصرف‌کننده».

مثل هر قالب `source: git` دیگری (شروع با Node.js، ASP.NET Core، لاراول) — مخزن کد را شما می‌آورید؛
Harbora می‌سازدش.

## قدم ۱ — گرفتن توکن از BotFather

۱. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید.
۲. دستور `/newbot` را بفرستید و اسم و username ربات را بدهید (username باید به `bot` ختم شود).
۳. BotFather یک توکن به این شکل برمی‌گرداند: `123456789:AAExampleTokenDoNotUseThisOne`

توکن را جایی امن نگه دارید — همان چیزی است که چند خط پایین‌تر در فرم استقرار Harbora وارد می‌کنید.

## قدم ۲ — استقرار قالب

۱. **قالب‌ها** › دنبال «Telegram» بگردید › روی کارت **Telegram Bot (long-polling)** بزنید ›
   **استقرار**.
۲. **نام پروژه** و **نام برنامه** را بدهید.
۳. بخش **منبع کد**: آدرس مخزن Git خودتان را بدهید (کد قدم ۳ همین فصل را همان‌جا بگذارید) و در صورت
   نیاز برنچ را مشخص کنید.
۴. بخش **پیکربندی لازم**: فیلد `TELEGRAM_BOT_TOKEN` را می‌بینید — به‌صورت رمز (نقطه‌چین) نمایش داده
   می‌شود، چون این مقدار secret علامت خورده. توکنی که از BotFather گرفتید را همین‌جا بچسبانید.

   > این فیلد با کلید اصلی پنل رمزنگاری می‌شود، درست مثل رمز دیتابیس یا کلید API باکت. برخلاف
   > کلیدهای داخلی (مثل `APP_KEY` قالب لاراول) که اگر خالی بماند خودش یک مقدار تصادفی می‌سازد،
   > این یکی را Harbora نمی‌تواند حدس بزند — توکن را فقط تلگرام صادر کرده.

۵. **ساخت و استقرار** را بزنید.

## قدم ۳ — اسکلت کد (Node.js)

قالب فقط اسکلتِ توضیح‌شده در همین فصل را می‌شناسد؛ کد را در مخزن خودتان می‌گذارید. کمترین حالت
ممکن — بدون هیچ پکیج بیرونی، فقط `fetch` توکار Node — این‌طور است:

```json
// package.json
{
  "name": "harbora-telegram-bot-starter",
  "version": "1.0.0",
  "type": "module",
  "engines": { "node": ">=18" },
  "scripts": { "start": "node index.js" }
}
```

```js
// index.js
const token = process.env.TELEGRAM_BOT_TOKEN;
if (!token) throw new Error("TELEGRAM_BOT_TOKEN is not set");

const api = `https://api.telegram.org/bot${token}`;
let offset = 0;

async function tick() {
  // timeout=50: Telegram holds the connection open and answers the moment an update
  // arrives, or after 50s with an empty list — this IS the long-polling loop, not a
  // sleep-and-retry one.
  const res = await fetch(`${api}/getUpdates?offset=${offset}&timeout=50`);
  const { result: updates } = await res.json();

  for (const update of updates) {
    offset = update.update_id + 1;
    const chatId = update.message?.chat?.id;
    const text = update.message?.text;
    if (!chatId || !text) continue;

    await fetch(`${api}/sendMessage`, {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ chat_id: chatId, text: `Echo: ${text}` })
    });
  }
}

// A worker restarts like any container; one failed tick must not kill the process —
// it should log and try again on the next loop.
async function run() {
  for (;;) {
    try {
      await tick();
    } catch (err) {
      console.error("poll failed:", err);
      await new Promise((r) => setTimeout(r, 3000));
    }
  }
}

run();
```

همین دو فایل، پوش‌شده به مخزنی که در قدم ۲ دادید، یک ربات کار می‌سازد که هر پیام را echo می‌کند.
منطق واقعی — پاسخ به سفارش، اتصال به دیتابیس، هرچه لازم دارید — همین‌جا اضافه می‌شود؛ اسکلت فقط
حلقهٔ polling و رمزگشایی توکن را حل کرده.

## قدم ۴ — بررسی اینکه ربات زنده است

چون این اپ دامنه ندارد، صفحه‌ای برای باز کردن در مرورگر وجود ندارد. زنده بودنش را از **لاگ‌های اپ**
ببینید (همان بخشی که در [فصل ۳ — اپلیکیشن‌ها](03-applications.md) توضیح داده شد) — یا ساده‌تر، به
ربات در تلگرام پیام بدهید و منتظر جواب echo بمانید.

## اختیاری — حالت Webhook (نیازمند آدرس عمومی فانکشن)

Long-polling پیش‌فرض این قالب است چون بدون هیچ آدرس عمومی‌ای کار می‌کند. اگر ترجیح می‌دهید تلگرام
خودش هر آپدیت را با یک درخواست HTTP به شما تحویل بدهد (webhook)، این حالت جایگزین از **فانکشن عمومی**
استفاده می‌کند — قابلیتی که به این قالب مربوط نیست، بلکه یک فانکشن HTTP جداست:

۱. **فانکشن‌ها** › **فانکشن‌اپ تازه** — یک اپ فانکشن با زمان اجرای دلخواه بسازید.
۲. داخل آن اپ، یک فانکشن با تریگر **HTTP** بسازید (یا همان فانکشن `hello` پیش‌فرض را ویرایش کنید)
   و کدش را بنویسید تا بدنهٔ JSON دریافتی از تلگرام (یک شیء `Update`) را بخواند و پاسخ بدهد — دقیقاً
   همان منطق `sendMessage` بالا، این‌بار داخل یک تابع فانکشن به‌جای یک حلقهٔ بی‌پایان.
۳. تیک **عمومی** را بزنید. هشدار کنارش را جدی بگیرید: «هرکسی در اینترنت می‌تواند این آدرس را بدون
   کلید یا امضا صدا بزند» — درست است، و برای این حالت لازم است: تلگرام هم «هرکسی» است.
۴. **ذخیره** کنید و بعد **انتشار** بزنید — آدرس فانکشن تا وقتی منتشر نشود پاسخ نمی‌دهد.
۵. آدرس کپی‌شده (به شکل `https://{دامنهٔ اپ}/{مسیر فانکشن}`) را به تلگرام معرفی کنید:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://YOUR-FUNCTION-URL"
```

پنل تماس‌های عمومی را نمی‌بیند — طبق همان قاعده‌ای که صفحهٔ فانکشن خودش می‌گوید، این تماس‌ها را در
**لاگ‌های اپ** پیدا می‌کنید، نه در تاریخچهٔ اجراهای فانکشن.
