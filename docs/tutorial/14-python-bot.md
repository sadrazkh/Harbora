# ۱۴ — ربات تلگرام با پایتون

این فصل یک ربات تلگرام پایتونی را از صفر تا «دارد کار می‌کند» می‌برد. برخلاف
[فصل ۱۰](10-telegram-bot.md) که Node.js است، اینجا همه‌چیز پایتون است — و یک تفاوت مهم دارد که
پایین‌تر توضیح داده می‌شود: Node خودش در `package.json` می‌گوید کدام فایل را اجرا کند، پایتون چنین
فایلی ندارد.

> این فصل هم تصویر ندارد، به همان دلیل فصل‌های ۱۰ تا ۱۳: در نشستی نوشته شده که به پنلِ در حال اجرا
> و به Docker دسترسی نداشت. متن از روی خودِ کد پنل نوشته شده — نام فیلدها، متن دکمه‌ها و پیام‌های
> واقعی خطا همان چیزی‌اند که در سورس هست، نه حدس.

## چقدر طول می‌کشد

سؤال اولی که هرکسی می‌پرسد، و جوابش را کسی نمی‌نویسد:

| مرحله | زمان |
|---|---|
| گرفتن توکن از BotFather | ۱ تا ۲ دقیقه |
| پوش کردن دو فایل به یک مخزن گیت | ۲ تا ۳ دقیقه |
| پر کردن فرم استقرار در پنل | ۱ تا ۲ دقیقه |
| **اولین بیلد** (دانلود ایمیج پایه + `pip install`) | **۲ تا ۵ دقیقه** |
| بیلدهای بعدی (با کش) | ۲۰ تا ۶۰ ثانیه |

یعنی **بار اول حدود ده دقیقه، و از آن به بعد کمتر از یک دقیقه.** بیشترِ آن ده دقیقه صرف دانلود
`python:3.12-slim` و نصب پکیج‌هاست، نه کار شما.

## قدم ۱ — توکن از BotFather

۱. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید.
۲. `/newbot` بفرستید، اسم و username بدهید (username باید به `bot` ختم شود).
۳. یک توکن به این شکل می‌گیرید: `123456789:AAExampleTokenDoNotUseThisOne`

## قدم ۲ — دو فایل، با نام‌های دقیقاً همین

این مهم‌ترین قسمت این فصل است. **نام فایل را عوض نکنید.**

```
requirements.txt
bot.py
```

`requirements.txt`:

```
python-telegram-bot==21.6
```

`bot.py`:

```python
import logging
import os

from telegram import Update
from telegram.ext import Application, ContextTypes, MessageHandler, filters

# لاگ‌ها تنها راهی هستند که می‌فهمید ربات زنده است — این اپ دامنه ندارد که در مرورگر باز کنید.
logging.basicConfig(format="%(asctime)s %(levelname)s %(message)s", level=logging.INFO)

token = os.environ.get("TELEGRAM_BOT_TOKEN")
if not token:
    raise SystemExit("TELEGRAM_BOT_TOKEN is not set")


async def echo(update: Update, context: ContextTypes.DEFAULT_TYPE) -> None:
    if update.message and update.message.text:
        logging.info("message from %s", update.effective_chat.id)
        await update.message.reply_text(f"Echo: {update.message.text}")


def main() -> None:
    app = Application.builder().token(token).build()
    app.add_handler(MessageHandler(filters.TEXT & ~filters.COMMAND, echo))
    logging.info("bot starting — polling for updates")
    # long-polling: خودِ ربات به تلگرام وصل می‌شود. هیچ پورتی باز نمی‌شود و هیچ webhook ای لازم نیست.
    app.run_polling()


if __name__ == "__main__":
    main()
```

این دو فایل را به یک مخزن گیت پوش کنید. همین. نه Dockerfile لازم است، نه `Procfile`، نه چیز دیگری.

### چرا اسم فایل مهم است

Harbora وقتی مخزنی بدون Dockerfile می‌بیند، خودش یک Dockerfile می‌سازد. برای پایتون باید حدس بزند
کدام فایل را اجرا کند، چون پایتون — برخلاف Node که `npm start` را از `package.json` می‌خواند —
هیچ‌جا این را اعلام نمی‌کند. فهرست نام‌هایی که می‌شناسد این است:

```
app.py · main.py · wsgi.py · server.py · bot.py · run.py · start.py · __main__.py
```

اگر فایل شما هیچ‌کدام از اینها نباشد، **استقرار با خطا رد می‌شود** و پیام خطا همین فهرست را به شما
نشان می‌دهد. این عمدی است: تا همین اواخر به‌جای رد کردن، `app.py` را حدس می‌زد و ایمیجی می‌ساخت که
هرگز بالا نمی‌آمد — و چون سیاست ری‌استارت `unless-stopped` است، آن ایمیج بی‌نهایت بار کرش می‌کرد و
اپ در پنل «در حال اجرا» دیده می‌شد. اگر قبلاً چنین چیزی دیده‌اید، باگ بوده، نه شما.

اگر اسم فایلتان را نمی‌خواهید عوض کنید، قدم ۵ راه دیگری دارد.

## قدم ۳ — استقرار از قالب

۱. **قالب‌ها** › دنبال «Telegram» بگردید › کارت **Telegram Bot (Python, long-polling)** ›
   **استقرار**.
۲. **نام پروژه** و **نام برنامه** را بدهید.
۳. **منبع کد**: آدرس مخزن گیت خودتان و در صورت نیاز برنچ.
۴. **پیکربندی لازم**: فیلد `TELEGRAM_BOT_TOKEN` را می‌بینید، به‌صورت نقطه‌چین چون secret علامت خورده.
   توکن BotFather را همین‌جا بچسبانید.

   > این مقدار با کلید اصلی پنل رمزنگاری می‌شود. Harbora نمی‌تواند آن را بسازد — فقط تلگرام صادرش
   > کرده — و به همین دلیل `required` است و فرم بدون آن جلو نمی‌رود.

۵. **ساخت و استقرار**.

قالب اپ را از نوع **Worker** می‌سازد. یعنی: **بدون دامنه، بدون آدرس عمومی، بدون health check.**
این درست است و نباید نگرانش باشید — یک ربات long-polling به هیچ درخواست HTTP ای جواب نمی‌دهد، و
health check ای که منتظر جواب بماند تا ابد منتظر می‌ماند و استقرار سالم را «خراب» اعلام می‌کند.

## قدم ۴ — از کجا بفهمید کار کرده

سه جا را به ترتیب نگاه کنید.

**۱. لاگ استقرار.** دنبال این خط بگردید:

```
No Dockerfile — auto-detected Python (entry: bot.py); using a generated build.
```

آن `(entry: bot.py)` مهم‌ترین چیزی است که در این صفحه می‌بینید: **دقیقاً می‌گوید چه فایلی قرار است
اجرا شود.** اگر اسم دیگری آنجا نوشته بود، همان‌جا فهمیده‌اید مشکل کجاست، نه نیم‌ساعت بعد.

**۲. لاگ‌های اپ.** باید این را ببینید:

```
bot starting — polling for updates
```

اگر لاگ **خالی** بود، قبلاً این ابهام وجود داشت که یعنی ربات مرده یا فقط چیزی چاپ نکرده — چون
پایتون وقتی خروجی‌اش ترمینال نیست آن را بافر می‌کند و ممکن بود ساعت‌ها چیزی بیرون نیاید. حالا
Dockerfile تولیدشده `PYTHONUNBUFFERED=1` دارد، پس **لاگ خالی یعنی واقعاً چیزی چاپ نشده.**

**۳. خودِ تلگرام.** به ربات پیام بدهید. باید `Echo: ...` برگردد.

## قدم ۵ — اگر حدس اشتباه بود

اگر فایل اصلی شما اسم دیگری دارد (`telegram_bot.py`، `src/main.py`، هر چیزی)، لازم نیست اسمش را
عوض کنید و لازم نیست Dockerfile بنویسید.

در صفحهٔ اپ، بخش **دستور راه‌اندازی** (Start command) را پیدا کنید و بنویسید:

```
python telegram_bot.py
```

**ذخیره** کنید. پیام «با استقرار بعدی اعمال می‌شود» را می‌بینید — یعنی باید یک بار دیگر استقرار
بزنید تا اعمال شود. خالی گذاشتن این فیلد یعنی «همان‌طور اجرا کن که ساخته شده».

این فیلد برای هر سرویس همیشه‌درحال‌اجرا هست، نه فقط ربات‌ها — هر Worker پایتونی، هر مصرف‌کنندهٔ صف.

## مشکلات رایج

**ربات جواب نمی‌دهد ولی لاگ می‌گوید `polling for updates`.** توکن درست است و ربات وصل شده. تقریباً
همیشه یعنی در تلگرام روی **Start** نزده‌اید، یا دارید به ربات اشتباهی پیام می‌دهید.

**`Conflict: terminated by other getUpdates request`.** دو نسخه از همین ربات هم‌زمان در حال polling
هستند. تلگرام فقط یکی را اجازه می‌دهد. تعداد replica این اپ باید **۱** باشد — یک ربات long-polling
افقی مقیاس نمی‌گیرد.

**استقرار با «no recognisable stack» رد شد.** یعنی `requirements.txt` در ریشهٔ مخزن نیست، یا هست و
هیچ‌کدام از نام‌های فهرست قدم ۲ کنارش نیست. پیام خطا خودش فهرست را می‌نویسد.

**`manage.py` دارید.** این جنگو است و این buildpack جنگو را خودکار تشخیص نمی‌دهد — عمداً، چون
`python manage.py` بدون آرگومان فقط راهنما چاپ می‌کند و خارج می‌شود. برای جنگو Dockerfile خودتان را
بنویسید.

## حالت webhook

اگر به‌جای long-polling می‌خواهید تلگرام خودش هر آپدیت را با یک درخواست HTTP تحویل بدهد، آن راه
یک چیز دیگر است: یک **فانکشن عمومی**، نه این قالب. همان بخش «اختیاری» در انتهای
[فصل ۱۰](10-telegram-bot.md) این را قدم‌به‌قدم توضیح داده و برای پایتون هم بدون تغییر صدق می‌کند.

برای شروع، long-polling را انتخاب کنید: هیچ آدرس عمومی‌ای لازم ندارد و هیچ چیزی نیست که تنظیمش را
اشتباه کنید.
